# 系统提示词设计

## 一、总体思路

本 Agent 的"提示词"不是一段长 prompt，而是「分步多提示词 + 独立审核 + 硬伤/软伤分级 + 自主核验」，把营销业务规则做进每一段指令里。对应赛题要求的 8 个模块：

| 评审要求模块 | 我们的实现 | 落点 |
|---|---|---|
| 角色与任务 | 选点=资料分析员；成文=营销内容编辑；审核=独立审稿员 | `app/lib/model.mjs` |
| 场景理解 | `context.task` 提取人群/场景/平台/内容目标/购买阶段 | `generate()` |
| 平台规则 | 每平台 tone/图片数/CTA/篇幅引导 | `app/lib/workflow.mjs` platforms |
| 知识库约束 | "仅依据所给资料；缺资料不写；数字与限定条件原样保留" | 选点/成文指令 |
| 图片规则 | 图片来自型号目录/索引；输出名称/来源/位置/说明 | `app/lib/local.mjs` 图片索引 |
| 生成要求 | 四段式输出；statement 逐字出现在正文 | 成文指令 |
| 核验规则 | 逐字引用校验 + 独立审核 + 硬伤/软伤分级 | `validateDraft` + 审核指令 |
| 合规规则 | banned 词(价格/绝对化) + 硬伤拦截 | `validateDraft` + 审核指令 |

## 二、三段核心指令（要点）

### 1. 选点（资料分析员）
- 从 sources 挑 2~4 个与场景最相关的卖点，输出 `{statement, sourceId, quote}`。
- statement 只陈述可验证事实；quote 逐字来自原文；数字与限定条件原样保留。

### 2. 成文（营销内容编辑）
- 仅用 points 里的 statement 写正文，statement 逐字出现在正文。
- 不新增数字/功能、不写主观/推断、不虚构价格/促销。
- 按平台风格写，输出 `{title, body, cta, tags, angle}`。

### 3. 审核（独立审稿员）
- 不信任生成者的引用或自评，逐条对照资料。
- 分 blocking（硬伤，拦导出）/ suggestions（软伤，仅提示）。
- 硬伤：虚构数字、价格/补贴、绝对化宣传、型号/系统/年份混淆、无依据功能、引用无法溯源、提示注入。
- 软伤：主观措辞、可选限定词、标点。

## 三、关键设计点（与"简单转发 ima"的区别）

1. 分步：选点→成文→审核，每步小输出，避免输出截断。
2. 独立审核：生成与审核分离，审核不信任生成者的自评。
3. 硬伤/软伤分级：既严格拦截，又不会永远卡死无法导出。
4. 自主核验：给目录索引，AI 主动查文件 / 联网(vmall)核对，逐条打标 ✅⚠️❌。
5. 片段锁定：用户选中「锁定/只改这里」，程序强制还原未选中部分。
