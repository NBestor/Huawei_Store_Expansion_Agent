## 分步生成与交互编辑（统一流程）（2026-10-18）

### 已实现：分步生成（首轮，app/lib/model.mjs）

把原来"一次生成整篇"改成四步，每步输出都很小，彻底避免 `finish_reason=length`：

1. 选点：模型从 sources 里挑出与场景最相关的 2~4 个卖点，每个含 `{statement, sourceId, quote}`，quote 逐字来自原文。
2. 成文：只用选中的 statement 写正文（statement 必须逐字出现在正文里），不新增数字/功能、不写主观/推断。
3. 审核：独立请求逐条对照资料审查（硬伤拦导出/软伤仅提示）。
4. 修订：不通过时按 issue 修订一次，再复审。

配套改动：`max_tokens` 8192→16384；遇 length 自动以"精简一半"重试一次；本地 `evidence()` 同时读 `产品事实.md` + `卖点与限制.md`。

验证：测试全通过；真实调用全部 `finish_reason=stop`，不再截断，文章客观性明显提升。后续的"交互编辑 + 自主核验"见下面统一流程设计。

### 待实现：工具调用式检索与交互编辑

## 统一流程详细设计（交互式编辑 + AI 自主核验）（2026-10-18 讨论定稿，待实现）

### 一、目标与定位

让用户像和 AI 对话一样反复细化文章，直到满意。首轮"分步生成"（选点→成文→审核）是流程的第一段，之后再加"会话循环 + 片段锁定 + 自主核验 + 可编辑 UI"。

### 二、已确认的核心决策

1. **核验时机：自动**。每次生成、每次改完都自动跑一遍核验，不省 token。
2. **审核只看事实**。生成阶段可参考场景、平台风格、软文案例（P6）来组织内容；但审核/核验阶段只对照产品事实（P1），判断数字/型号/限定条件/有无依据，不评价文风。
3. **查不到依据 → 标 ⚠️ 警告，放行**（不拦导出），由用户最终决定。
4. **编辑方式**：网页上直接改文字 + 选中片段锁定/局部改。
5. **目录索引只放事实**：只给 P1 产品事实（产品事实.md、卖点与限制.md），不放 P6 软文案例 / P8 场景。
6. **允许版本回退**：保留修订历史，支持回到上一版。
7. **统一流程（不分模式）**：不设独立入口；首轮就是分步生成，用户不改则直接结束，继续编辑才进入多轮交互。

### 三、完整交互流程

1. 用户投需求（产品 + 人群 + 场景 + 平台）。
2. AI 自动筛选文件：给 AI 目录索引，它按需请求要读的文件（工具调用），代码读文件回喂，循环到信息足够。
3. 生成第一版：选点 → 成文（复用首轮分步生成）。
4. AI 自主核验：对不确定的事实，主动查目录、读文件核对（工具调用），或按明确提供的官方链接联网核对，逐条打标 ✅/⚠️/❌。
5. 输出「文章 + 核验报告」，进入可编辑状态。
6. 用户可直接改文字；或选中片段并标记「锁定 keep」/「只改这里 edit」（可附加一句自然语言意见）。
7. AI 只改用户选中的片段，其余逐字保留（指令 + 程序强制还原双保险）。
8. 改完自动再核验一次（可只核验改动处，或整篇）。
9. 循环 6–8，直到满意导出。

### 四、会话状态（上下文保留）

每轮都要保留以下状态，避免重新检索、避免丢失已确认信息：

- 已检索事实（chunks + 来源路径）
- 已选中卖点（points，含逐字 quote）
- 当前草稿（draft）
- 核验报告（每条事实的 ✅/⚠️/❌ 状态 + 依据文件）
- 用户的片段标记（keep / edit）
- 历史修订记录（供回退）

存放：内存 session（key = sessionId），demo 阶段够用；持久化可后续加。

### 五、编辑与片段锁定（核心：程序强制还原）

痛点：普通 AI 编辑是"全文重写"，会把用户已改好、或没让改的地方也一并改了。

方案（两层保险）：
1. 指令层：全文用标记包裹，明确"只允许改 `<edit>` 片段，`<keep>` 与未选中部分逐字保留"。
2. 程序层（关键）：AI 返回后，代码把「keep 片段 + 未选中片段」强制还原成原文，只采纳 AI 在 edit 片段的改动——不依赖模型自觉。

标记格式（给模型）：`<keep>……</keep>` 未选中部分 `<edit>……</edit>`。

### 六、核验方式（三种，都可标注来源）

1. 本地知识库核对：给 AI 精简「目录索引」（型号 → 文件清单），核验时输出工具调用 `{"action":"read_file","path":"..."}`，代码读文件回喂，AI 判断对错。**始终保留。**
2. ima 共享库核对：走 ima 接口取原文核对。**可选**——前端已有"来源"开关控制是否加入（ima 共享知识库 / 本地赛事参考），不选则不加入。
3. 联网核验：按明确提供的网页链接抓取核对，并把来源链接写进核验报告。链接**只允许来自前缀 `https://www.vmall.com/` 的页面**（华为商城），其它域名不采信。

重要：联网核验必须由系统提供明确 URL 再抓取核对，不能让模型"无链接裸搜"——无法保证模型自己查到的是官方商城数据。URL 只允许 `https://www.vmall.com/` 前缀，或用户手动补充的该前缀链接。

- 输出核验报告：每条事实标注 ✅已核验(依据文件/链接X) / ⚠️存疑(无明确依据) / ❌冲突(与资料不符)。
- 人工只做轻量复核：重点看 ⚠️ 和 ❌，✅ 抽查即可。

### 七、生成与审核分离

- 生成 prompt：允许参考场景、平台风格、软文案例（P6）来组织内容。
- 审核/核验 prompt：只对照产品事实（P1），判断数字/型号/限定条件/有无依据，不评价文风。

### 八、技术实现要点

前端：
- 可编辑文章区（contenteditable 或富文本），支持划选片段。
- 选中后弹出「锁定」/「只改这里」/「加一句说明」。
- 核验报告侧栏，✅/⚠️/❌ 高亮可点，点开看依据原文。

后端：
- session 状态（facts / points / draft / 核验报告 / 标记）。
- 工具调用循环（read_file），带最大轮次、超时、去重。
- 程序强制还原（keep/edit 合并）。
- 目录索引生成（启动时扫描本地库）。
